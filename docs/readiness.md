# Documentation and Digital Public Goods readiness

Status: requirements and evidence plan, not completed compliance or recognition.

The release must include: a practical README; tested installation and first-run instructions; a worked illustrative tutorial; template compatibility and customized-scenario input reference; numerical methods and exact verification coverage; architecture and contribution guidance; data/export schemas; backup, restore and troubleshooting instructions; privacy/data-flow and security reporting information; maintainer/ownership and asset-license records; and an accessibility/testing statement.

Design against the [Digital Public Goods Standard](https://www.digitalpublicgoods.net/standard), including development relevance, open licensing, clear ownership, platform independence, documentation, portability, applicable privacy obligations, standards and proportionate safeguards. Maintain evidence and named unresolved gaps for each applicable criterion. The software license does not resolve rights to the framework workbook or third-party assets.

Before release, an independent technical reader should be able to install and run the documented public example without private files or maintainer intervention. An analyst should be able to complete the upload-to-briefing journey using the actual supplied instructions. Test open-runtime operation, supported platforms, numerical comparisons, recovery, export privacy and measured network behavior separately.

Formal recognition requires the relevant external review and registry process. Do not describe the project as certified, approved or recognized merely because this checklist exists.
